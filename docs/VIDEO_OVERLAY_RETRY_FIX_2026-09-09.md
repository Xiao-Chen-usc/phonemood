# 视频前台不出现、打开 PhoneMood 后才出现的提醒

用户补充：连续使用哔哩哔哩时未观察到悬浮窗，打开 PhoneMood 后卡片才出现并留在屏幕上。尚未获得该手机日志，不能确认后台停转、窗口限制或旧版本行为中的哪一种造成了这次案例。

用户进一步确认：期间手机顶部一直显示 PhoneMood 的小标志。这是常驻通知仍存在的证据，但不是协程计时循环持续成功执行的证据。不能据此断言进程被系统关闭，也不能排除服务仍在而轮询任务已经异常退出。

## 已确认的代码缺口与修改

1. 原悬浮窗仅按提醒最初生成时间计算五分钟有效期。通知在同一应用内重试时，悬浮窗不会跟随重试。现在以该提醒最近一次通知投递时间开启新的、有截止时间的卡片窗口；正式服务先投递通知，再协调卡片。
2. 原先允许“前台切换”无限期使待处理旧卡片重新满足展示条件。移除此入口，只有原始窗口或一次新的实际通知投递才能开启卡片窗口，打开 PhoneMood 本身不延长卡片期限。
3. 同一提醒发生新的投递时重新附加卡片，不再因为旧窗口对象还在就直接复用它。
4. 原监测循环在重试保护之外读取设置，读取异常会结束循环，直到再次启动服务。设置读取现在位于保护范围内，保存错误信息本身失败也不会结束监测循环。
5. 不再仅依据窗口对象存在就静音系统提醒。系统通知是否发声仍由通知渠道与用户系统设置决定。

保留已有的十五分钟独立检查点、五分钟通知重试（最多三次）、滑走只取消当前提醒、隐私锁屏设置。未使用强制打开评分 Activity 或全屏通知的方式抢占其他应用。

## 验证

策略单元测试覆盖：同一视频应用内的迟到通知重试开启新卡片窗口；五分钟后到期；关闭、已回答和稍后提醒仍有效。

新增模拟器测试覆盖：不切换视频前台，旧检查点收到新的投递时间后显示卡片；随后打开 PhoneMood 或切换其他应用，均不能无限延长这次展示。

另保留连续十二个十五分钟节点、交替滑走或忽略卡片的回归测试。模拟器使用合成使用事件和加速时间，不代表在真实哔哩哔哩内持续播放三小时。
