# 回顾与导出流程

## 核心流程

今天（即时觉察） → 趋势（默认近 7 天） → 选择日期或周期 → 阅读记录和完整性 → 导出／分享所选记录。

将原“每日导出”、原始“使用记录”和“分析”收敛为“趋势”，避免用户先生成 JSON 才能理解记录。底部只保留今天、趋势、设置三个入口；原始日志不再成为用户可见的主要页面。

## 日期选择

- 默认昨天。可向前翻一天查看前天，也可用日期选择器查看任意历史单日。
- 上周明确指上一完整自然周，周一至周日。
- 近 7 天和近 30 天截至昨天，排除尚未结束的今天。
- 更早／更晚一期按当前 1、7、30 天长度翻页，不自动进入今天。
- 周期内点击某日进入单日回顾，可返回原周期。
- 今天单独标为“今日预览”，结果和导出标记为包含进行中日期。
- 日期以数据库记录时区为准，并在页面显示该时区；夏令时按实际日界线处理。

## 结果与数据状态

日期结束不代表记录完整。页面分别显示进行中、记录完整、记录不完整、暂无记录。缺少记录用破折号和说明呈现，不解释为零使用。

单日先展示使用时长、评分与应用用时；多日增加日均、逐日记录和关联分析。心情评分默认展示最近 5 条，可展开；30 天明细按需展开。未达到分析门槛也能阅读和导出原始记录。

## 导出

导出和分享使用页面当前结果的同一个快照，文件名包含起止日期。历史查询和计算均使用所选时间范围，剔除结束边界之后的评分；记录生成时间与周期结束时间分开。JSON 的 includes_ongoing_day 从实际日期计算，schema 允许 true / false。刷新失败或刷新中暂时禁用导出，防止错误地认为已导出最新结果。

原有后台每日自动保存保留，原文件不会删除。前台不再以自动保存的文件列表作为历史数据入口，直接从本机记录生成回顾。

## 验证

增加历史单日边界、完整历史周、夏令时单日和未来日期拒绝测试。运行 debug 构建、单元测试和 lint，并在现有模拟器检查回顾入口。
